# Skill System Changes (since `cda614d`)

Branch: `v4_agent_skill` | 18 files modified, 4 files added (not yet committed)

In short: **two new skills (closer/farther, rotate by an angle); every skill now understands the user and the walls as anchors; fixed "wrong skill picked" and "passed without being checked"; rotations now pivot on the object's geometric centre.**

---

## 1. New skills

### `proximity_placement` — closer / farther
> "move both chairs closer to the table", "bring the lamp closer to me", "push the sofa away from the TV"

- **Each object moves on its own side of the anchor**: a chair left of the table moves right, one on the right moves left. They are never pulled to the same spot.
- An object moves only along the axis where it is separated from the anchor. If it sits off a corner of the anchor, both gaps shrink by the same fraction, so it moves diagonally.
- **closer**: the gap is halved, down to 0.1 m to an object or 0.5 m to the user.
- **farther**: the gap grows by at least 0.3 m each time.
- A stated distance ("0.5 m closer") replaces the halving.
- Objects move nearest-first, and each one stops 0.1 m short of anything in its path.
- The anchor can be an object, the user ("me"), or a wall ("the left wall").
- Files: `tools/proximityPlacement.py`, `skills/proximity_placement/`

### `rotate_placement` — rotate by an angle
> "rotate the table by 180 degrees", "turn the desk 90 degrees anticlockwise", "turn the sofa around"

- New yaw = current yaw ± degrees. Clockwise seen from above is negative, anticlockwise is positive.
- **Turns about the bounding-box centre**, so the object spins in place instead of swinging around its model origin (see §5).
- Used only when the user gives an angle. "turn the chair to face the TV" still goes to facing.
- Files: `tools/rotatePlacement.py`, `skills/rotate_placement/`

## 2. The user as an anchor ("me")

Skills used to accept only scene objects as anchors, so "face me" found no target and the LLM had to guess. One real failure: the LLM used the headset height (y = 1.8) as z, and the chairs turned toward a point outside the room.

- New `user_anchor()` in `_common.py`: the user is **a point** at the headset's x and z (**never y**), facing the user's yaw, with no bounding box.
- Skills that now accept the user:
  | Skill | Example |
  |---|---|
  | facing_placement | "rotate all chairs to face me", "add a chair facing me" (placed 0.5 m in front of you) |
  | distance_placement | "1m in front of me", "2m to my left" (left/right from **the user's own view**) |
  | around_placement | "arrange the chairs around me" (a ring 0.5 m from you) |
  | proximity_placement | "closer to me" |
- New `user_direction_axis()` in `orientation.py` gives the user's own front/back/left/right.

## 3. Walls as anchors

- New `wall_anchor()` in `_common.py`: the back/front/left/right wall is a zero-thickness face on that room boundary.
- **proximity**: "move the desk closer to the left wall" ✅
- **facing**: "turn the chair to face the back wall" faces the wall square-on, not its midpoint ✅
- distance and around **do not accept walls**: their maths would line the object up with the wall's midpoint or arrange things "around" a wall, which makes no sense.
- A `wall_placement` skill (put against a wall / N m from a wall) was added and then **removed**. Commands like "attach all chairs to the back wall" are now handled by the LLM.

## 4. Stopping wrong skill picks and false passes

### 4.1 Trigger words (`TRIGGER`)
The LanguageAgent often forced a "close enough" skill onto a command. For example, "attach all chairs to the back wall" was mapped to proximity, and later to facing — which turned the chairs to face the back wall.

Each skill can now define a `TRIGGER`. If the **user's original words** (not the LLM's paraphrase) contain none of them, the skill choice is dropped and the regex fallback or the LLM takes over.

| Skill | Words that must appear |
|---|---|
| facing_placement | face / facing / toward / look at |
| proximity_placement | closer / nearer / farther / further / away from / toward |
| distance_placement | a number + unit (1.5 meters, 2m, 50 cm, one meter) |
| around_placement | around / surround / encircle / circle |
| on_placement | on / onto / atop |
| rotate_placement | rotate/turn/spin/flip **and** an angle ("N degrees", "around", "quarter turn") |

- Implemented in `registry.py` through `validate_call(..., prompt=...)`. `languageAgent.py` passes in the user's original words.
- Log example: `[SKILL] 'proximity_placement' rejected: "..." has none of its trigger words`

### 4.2 A skill that cannot run no longer checks the result
Before: when a skill could not run, the LLM placed the objects, but verification still checked that result against the skill's rules. Correct results were rejected this way.

- When a skill reports it cannot run, SceneAgent marks it `skill['applicable'] = False` and **no longer puts that skill's rules into the LLM prompt**.
- The orchestrator sees the mark, skips the skill's check, and runs only the collision and room-bounds checks. The log says `not applicable — LLM result not skill-checked`.
- If the skill did run and the LLM is only retrying after a collision, the skill's check **still runs**.

### 4.3 A missing anchor is no longer a silent pass
Before: when the anchor could not be found, all 5 skills' postconditions returned `[]`. The log said "postcondition satisfied", but nothing had been checked. They now return a `fixable: False` violation (`_common.unresolved()`).

## 5. Rotation pivots on the geometric centre

**Problem**: an object's `position` is the model's origin, and the frontend also rotates around that origin. On the desk, the origin is 0.72 m from the geometric centre, so a 180° turn swung the desk about 1.45 m around one corner. Cabinet, lamp and other assets have the same issue.

**Changes**:
- `tools/rotatePlacement.py`: `rotate_about_centre(obj, new_yaw)` recomputes `position` so the bounding-box centre (x, z) stays where it was.
- **Every place that turns an object uses it**:
  - rotate_placement, and facing_placement when it only turns the object
  - SceneAgent's new `_turn_in_place_about_centre()`: any object whose rotation changed but whose position did not (turned by the LLM or by the existing `_compute_rotation` code) is re-centred.
- **Facing angles are always measured from the bounding-box centre**: `_common.yaw_toward()` is shared by the facing skill, SceneAgent's facing post-process, and facing's postcondition. Before, the post-process recomputed the angle from the model origin. That overwrote the skill's result, the postcondition then failed, and SceneAgent kept retrying.
- **CodeAgent**: on a `rotate` it used to write only the rotation, so the corrected position was lost. It now also writes the position when it changes.
- **Verification**: the POS/ROTATE collision check used the rotation from before the turn. It now uses the new rotation.

---

## 6. Other fixes

- The facing and around tools used the anchor's **model origin** as its centre. They now use its **bounding-box centre**. Facing a desk whose origin is far off-centre used to be about 20° off.

## 7. New constants (`tools/spacing.py`)

| Constant | Value | Meaning |
|---|---|---|
| `PROXIMITY_RATIO` | 0.5 | fraction of the gap kept on each "closer" |
| `PROXIMITY_MIN_STEP` | 0.3 | minimum move (m) on each "farther" |
| `PROXIMITY_MIN_GAP` | 0.1 | closest an object may come to another object (m) |
| `USER_MIN_GAP` | 0.5 | closest an object may come to the user (m); also the gap used when around/facing place things near the user |

These values are filled into SKILL.md automatically (`$NAME`), so the LLM sees the same numbers the tools use.

## 10. Known issues (not fixed yet)

1. **around_placement makes the ring too small.** When the anchor is diagonal, the chairs that face it are diagonal too, so each chair's bounding box grows from 0.52 m to 0.72 m. The ring radius still uses 0.52 m, so the first placement collides. On retry the LLM moved only the two chairs that collided, and the ring was no longer even. Suggested fix: compute the radius from the chair's diagonal.
2. **"add a lamp and place it on the right side of the desk" was classified as POS/ROTATE.** It skipped the AssetAgent, so no lamp was created, and verification failed without printing why. Suggested fix: force ADD/DELETE when `primary_action == 'add'`, and log the reason for these silent verification failures.
3. **"around me" next to a wall.** The wall squeezes the ring, and some chairs end up closer than 0.5 m to the user. around's postcondition does not check for "too close".
4. **rotate_placement finds objects by name.** "rotate the table" when the object is named "desk" finds nothing and falls back to the LLM. The LLM matches it correctly and the turn is still re-centred, so the result is right, but the skill is not used.
